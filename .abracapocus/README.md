# ABRACAPTURE

## Purpose

Build Abracapture as a polished standalone Linux audio-capture utility for PipeWire. The product must automatically discover available application streams, system/output monitor streams, and hardware inputs; help users identify sources with live activity, waveform, and level visualization; capture through a realtime-safe native PipeWire engine; preserve a lossless master at the negotiated native format whenever possible; support WAV and FLAC masters; optionally create derived lossless/lossy exports after capture; provide auto-start/auto-stop, pre-roll/post-roll, capture-integrity reporting, configurable output directories and naming, history, settings, CLI automation, and a polished Qt 6.11 Qt Quick GUI. Use C++20, CMake, Qt Quick/Qt Quick Controls, PipeWire 0.3 APIs, libsndfile for WAV/container writing, libFLAC where required for full FLAC bit-depth support, and the ffmpeg executable only for optional post-capture exports/resampling. Do not build a DAW, editor timeline, plugin host, VST, or JUCE application. Do not place file I/O, compression, process spawning, allocation-heavy UI work, or blocking synchronization in the PipeWire realtime callback. The implementation must expose whether capture was native, quantized, resampled, or otherwise converted rather than presenting upsampled audio as higher-resolution source material. Materialize exactly the 32 hinted tasks: one task per task_hints entry and no additional implementation tasks. Codex routing was empirically validated on the target Microsoft Surface with codex-cli 0.147.0 using ChatGPT authentication: gpt-5.6-sol with xhigh reasoning effort, gpt-5.6-terra with high reasoning effort, and gpt-5.6-luna with medium reasoning effort all returned exit code 0 and the expected smoke-test response. The task_hints schema does not currently carry a reasoning-effort field, so do not add an unsupported key. Execution policy is: Sol tasks should use xhigh effort, Terra tasks high effort, Luna tasks medium effort once Abracapocus codex_cli/task routing has an explicit supported pass-through for model_reasoning_effort; until then, the validated model pins remain authoritative and effort must not be silently assumed by the plan. Antigravity routing was empirically validated on the target Microsoft Surface with agy 1.1.13. The executable Google model slugs returned by `agy models` include gemini-3.7-flash-{low,medium,high}, gemini-3.6-flash-{low,medium,high}, gemini-3.5-flash-{low,medium,high}, and gemini-3.1-pro-{low,high}. Smoke tests succeeded for gemini-3.7-flash-high, gemini-3.7-flash-medium, gemini-3.6-flash-medium, gemini-3.5-flash-medium, and gemini-3.1-pro-high. For these Gemini selections, effort is part of the model slug and a separate `--effort medium` argument is rejected. Abracapture therefore uses antigravity_cli with model `gemini-3.7-flash-medium` for its eight AGY tasks. Do not route Abracapture tasks to Claude/Opus through AGY.
